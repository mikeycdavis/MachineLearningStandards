# v1.2 — the frozen corpus, measured across three versions

**Date:** 2026-08-09 · **Compared:** `v1.0.0` · `v1.1.0` · `v1.2.0`, each run from its own tagged
tree · **Targets:** `Numerai`, `kaggle`, `bitgrit`, `ultralytics/yolov5`, **all four unmodified**.

The earlier versions were materialised from their tags with `git archive` and run as they were
released. No target was adjusted, cleaned, or re-bootstrapped to make a version look better.

---

## The headline, and it points downward

Nothing about these repositories changed between the three runs. Their scores did.

| Target | `v1.0.0` | `v1.1.0` | `v1.2.0` |
| --- | --- | --- | --- |
| `Numerai` | 67% | 67% | **0%** |
| `yolov5` | 88% | 80% | **50%** |

Every point of that decline was a pass the framework was not entitled to. `yolov5` at 88% had been
credited with a model card, a dataset card, and a baseline that `init` had written moments earlier;
with dataset versioning it does not do; and with two prohibitions whose detectors cannot read a word
of its dialect. The repository was the same repository at 88% and at 50%.

**A falling score across versions, with the corpus held fixed, is the measurement this release is
for.** Under the release philosophy in `CHANGELOG.md`, a version is better when its unknowns
correspond more accurately to what the system does not know — and the mechanism by which a score
falls is unknowns being reported instead of assumed.

## Where the passes went

`yolov5`, rule by rule. `passed` in `v1.0.0`, and what each became.

| Rule | `v1.0.0` | `v1.1.0` | `v1.2.0` | Why it moved |
| --- | --- | --- | --- | --- |
| `deployment.model-card` | passed | insufficient-evidence | insufficient-evidence | scaffolding was being read as evidence |
| `data.provenance-documented` | passed | insufficient-evidence | insufficient-evidence | same |
| `evaluation.baseline-exists` | passed | insufficient-evidence | insufficient-evidence | same |
| `data.version-pinned` | passed | passed | **insufficient-evidence** | model-artifact logging is not dataset versioning |
| `leakage.no-preprocessing-leakage` | passed | passed | **not-evaluated** | no scikit-learn dialect to read |
| `split.no-test-set-tuning` | passed | passed | **not-evaluated** | same |
| `reproducibility.experiment-config-recorded` | passed | passed | passed | `wandb.init(config=opt)` genuinely records the parameters |
| `reproducibility.seeds-recorded` | passed | passed | passed | `init_seeds(..., deterministic=True)` |

Two survive. Both survive because a detector positively saw the thing the rule asks for — which is
the property the [negative-evidence audit](../../design/negative-evidence-audit.md) identified in
every sound check.

`reproducibility.experiment-config-recorded` is the one worth dwelling on. The v1.2 subject test
made it stricter, and its answer on this target did not change: the call really does hand the
tracker the parameter set. A fix that corrects the reasoning without moving an answer that was
already right is the shape a fix should have.

## Evidence requests

| Target | `v1.0.0` | `v1.1.0` | `v1.2.0` |
| --- | --- | --- | --- |
| `Numerai` producible / human | 2 / 35 | 5 / 36 | **5 / 38** |
| `yolov5` producible / human | 0 / 35 | 3 / 35 | **4 / 37** |

Both totals rose again, and the human column carries the increase. That is the coverage demotions
arriving where they should: a rule whose detector could not read the target's dialect is human
judgement, and no additional file will change that.

**This ratio must not be optimised.** It has now risen across two consecutive releases, and both
times for the right reason. A future version that reduces it should be required to show which
mechanism newly establishes what, rather than which unknown stopped being reported.

## Scope

| Target | `v1.0.0` | `v1.1.0` | `v1.2.0` | Basis |
| --- | --- | --- | --- | --- |
| `Numerai` | 20,000 (cap) | 147 | **148** | git-owned — 147 tracked, 1 untracked, 0 ignored |
| `bitgrit` | 20,000 (cap) | 41 | **41** | git-owned |
| `yolov5` | — | 144 | **144** | git-owned |
| `kaggle` | 20,000 (cap) | 20,000 (cap) | 20,000 (cap) | heuristic — git still declines under `safe.directory` |

Evidence citing unowned code: **0 across all four targets**, unchanged from v1.1.

The single-file movement on `Numerai` is the whole visible effect of the ownership change on a
committed corpus, which is exactly right: these are repositories with their work already committed.
The defect it fixes appears at the moment of adoption, not afterwards, and the acceptance test is
the one the fourth adoption isolated:

```text
completed MODEL_CARD.md, untracked   →  insufficient-evidence,  80%, 5 scored rules
completed MODEL_CARD.md, git add     →  passed,                 83%, 6 scored rules
```

Identical bytes. Under v1.2 both states give the same disposition, and a permanent regression test
asserts it.

`kaggle` is unchanged and still truncating. Where git declines, a heuristic cannot know that a
project ignores its own data directories. The limitation is disclosed rather than fixed, and it
remains the operator's git configuration to resolve.

## What did not change

- **No standard was modified.** Four adoptions and three releases; the normative documents are
  untouched.
- **No rule was reclassified, exempted, or lowered.** The catalog baseline needed no relock.
- **No new automation and no new coverage.** Still 10 of 45 rules machine-examined across 25 of 25
  standards. v1.2 removed confidence; it added no reach.
- **No target was modified** to produce any number in this document.

## Mutation tests

Ten new tests in `test/v12-remediations.test.mjs`, each reintroducing the defect rather than
checking today's fixtures are green:

- staging a file is shown to change nothing, and the old tracked-only scope is shown to miss the
  operator's work that the new scope finds;
- an unignored virtualenv and a `node_modules` tree are shown to stay out of the widened scope —
  the regression the fix could have caused;
- `.gitignore` is shown still to be decisive, because it is the project's own statement;
- a `log_artifact(type="model")` file is shown not to satisfy dataset versioning, and a
  `use_artifact(type="dataset")` file is shown still to satisfy it;
- a bare `wandb.init()` is shown not to establish a recorded parameter set, and `wandb.init(config=)`
  shown to establish it;
- a PyTorch-only project is shown to produce `not-evaluated` with a stated reason on both
  scikit-learn-shaped prohibitions, while a correct scikit-learn project is shown to keep both
  passes — the converse constraint, without which the check would be worthless.
