# v1.1 — the same three targets, measured against the frozen baseline

**Date:** 2026-08-09 · **Compared:** `v1.0.0` (tagged, unchanged) against the v1.1 remediations ·
**Method:** the identical read-only scans, on the identical repositories.

The four remediations were narrowly scoped to the evidence in the two adoption reports. No standard
was changed. No rule was reclassified, exempted, or lowered.

## The metric that should not be inflated

Evidence requests on `Numerai`, the target both versions evaluated end to end:

| | v1.0 | v1.1 |
| --- | --- | --- |
| Producible by an agent unaided | 2 | **5** |
| Requiring human judgement | 35 | **36** |

The producible count rose because rules that previously *passed by silence* now correctly ask for
evidence — the movement is more honest gaps surfaced, not more automation claimed. The
human-judgement count rose too, for the same reason. **No rule moved from human judgement to
automation, and none should be expected to.** That is the direction to keep watching: this ratio
improving because judgement was quietly converted into certainty would be a regression wearing the
appearance of progress.

## Two defects found *by* the remediation, and fixed

**A second silent pass, more general than the first.** Fixing the bootstrap exposed that a rule in
the evaluated set whose detector is gated behind a trigger reports `passed` when the trigger never
fires. A project with no data was being credited with documenting its data. The evaluator now
receives the set of rules a detector actually examined on *this* target, rather than the set it can
examine in principle. This is `invariant.no-silent-pass` in its general form, and it was the
highest-value thing the exercise found after the two headline defects.

**The scope reporter lied about a real repository.** `kaggle` is a git repository; git declined to
answer because of a `safe.directory` setting, and the first v1.1 draft reported "Not a git
repository". That is a false statement about someone's own project, and the two cases lead to
different actions. The reason is now carried through and printed verbatim:

```text
Scope was decided by structure rather than by git, because fatal: detected dubious ownership
in repository at 'F:/Repos/kaggle'. … this is an approximation of what the project owns rather
than an answer from it.
```

---

## What is still not fixed

**`kaggle` still truncates.** Where git declines, the heuristic cannot know that a project ignores
its own data directories, so the cap is still reached. The result is disclosed, and the scope note
now says plainly that it is an approximation — but the underlying limitation stands: **the ownership
model is only exact when git answers.** Resolving the target's git configuration would fix this
particular case, and that is the operator's decision rather than the tool's.

**The third-target generalisation is about shape, not provenance.** All three repositories share an
owner. A genuinely external target remains untested.

## Mutation tests

Each remediation is tested by reintroducing the defect and asserting the guard fires, not by
checking today's fixtures are green:

- the exact template row that manufactured compliance is asserted non-substantive;
- the v1.0 heading check is run against the current template and shown to accept it, beside the
  v1.1 check rejecting it;
- deleting the scaffold marker is shown not to defeat the guard, because the shipped-template
  comparison still catches it — while a genuinely edited document is still accepted;
- a fixture virtualenv containing a leaky file produces nothing by default and reproduces the
  original false positive under `--include-unowned`;
- a blocked verdict is asserted to carry `score: null`, beside an unblocked one that scores 100.
