## Outcome

**A verbatim claim can no longer be asserted and never tested, and what a claim is is written down.**

`design/architecture.md` §14 — *How a standard quotes the source* — states the contract beside §13:
a claim announces with a colon and asserts reproduction; it must be followed immediately by a
fenced block, blockquote or bullet list; a claim with no such block is a finding; only line
wrapping is normalized away. It also states what is deliberately **not** recognised, so an author
can write the form that is. ADR 0002's provenance chain, which previously said only that verbatim
claims are checked, now names the contract and points at §14.

**Recognition was tightened first, and separately, because the order matters.** While an
unresolvable claim was skipped, an over-matching regex cost nothing; the moment it becomes a
finding, every sentence wrongly called a claim is a false failure. The grammar is now: a line
ending in a colon that contains `reproduced` or `verbatim` alongside `from the source`, or the bare
`From the source:`. All 25 live claims — which are the same string, `Reproduced verbatim from the
source:` — are still recognised, so no compatibility exception was needed or added.

**The skip is gone.** A recognised claim with no supported block is a `no-block` failure carrying
its own remediation, and is not counted among the claims checked, because it was not checked.

**Measured, not asserted.** Live corpus: **25 claims checked, 0 unverified, 0 recognised claims
without a block**, and 25 lines recognised — checked plus no-block reconciles exactly. Both measured
prose shapes are ignored; all three block forms are accepted and each still fails when a backtick is
added to its quotation. Comparison semantics are untouched: `normalize` still collapses wrapping
only, and tests assert backticks and dashes remain significant.

**Four tests were red before the change** — the plain-paragraph false pass, a claim at end of file,
and the two recognition shapes — and four mutations bite: restoring the skip turns 2 red,
re-broadening the regex turns 2 red, dropping list support turns 2 red, and stripping backticks in
normalization turns 2 red.

Fourteen tests added in a new `test/fidelity.test.mjs`; the suite is 301 passing, 0 failing, and the
12-stage pipeline is green. The positional pairing model is unchanged, and a test asserts it.

## What

Write down what syntax must follow a "reproduced verbatim from the source" claim, and make a claim
with no supported block beneath it a finding instead of a silent skip.

`scripts/fidelity.mjs` matches a claim line and checks the block immediately after it — a fenced
block, a blockquote, or a bullet list. Where the following material is none of those, `blockAfter`
returns null and `if (!block) continue` passes the claim over without counting it and without
reporting it.

## Why

**The probe was run and reverted; this is measured, not hypothetical.** A section reading
`Reproduced verbatim from the source:` above a plain paragraph whose text appears nowhere in the
specification left the run at **25 claims checked, 0 unverified, exit 0**. A document asserted that
what followed was source text, the assertion was false, and the gate built to falsify exactly that
assertion said nothing.

**It is the same class [[FE-35]] closed, in the gate ADR 0013 cites as already mechanical.** The
`levels` defect was a section resolving to the wrong sentence and reporting agreement; this is a
claim resolving to nothing and reporting success. Both are a guard reporting a clean result over
input it did not actually check, which is the failure mode
[ADR 0013](../../adr/0013-the-prose-to-catalog-link-gets-a-guard.md) decision 4 refused for
`levels` — *"a check that quietly passes what it cannot read is worse than no check, because it
also reports success"* — and which `fidelity.mjs` still does.

**Neither half of the contract is written down.** That a claim sentence is what triggers the check
at all, and that a fence, blockquote or list must follow it immediately, are stated only in
`fidelity.mjs`'s own header. `design/architecture.md` §13 now states the normative-sentence
convention for `levels`; nothing states this one. An author quoting the source into a
twenty-sixth standard has the existing files to copy and nothing to read.

**This gate carries more than the others.** The twenty-three must-never rules reach the standards
by quotation. A prohibition that has been paraphrased is a prohibition that no longer says what its
author wrote, and the header records that the donor repository shipped that defect twice.

## What the implementation must confront

Measured at `7a5b5c4`, before any work:

| | |
| --- | --- |
| Claim lines followed by a supported block | 25 |
| Of those, blockquote form | 25 |
| Of those, fenced or list form | 0 |
| Claim lines with **no** supported block | **0** |

**The steady state already satisfies the rule.** Turning the skip into a finding produces zero
findings on the live corpus, so this needs no allowlist and no scoping exemption — the same
position [[FE-35]] was in.

**But the corpus cannot prove two of the three accepted forms.** Every live claim is a blockquote.
Fence and list are accepted by the code and exercised by nothing, so "the existing valid forms
remain accepted" has to be held by fixtures rather than by the real documents. A change that
silently dropped either would go unnoticed today.

**And the skip is currently masking a loose regex.** `CLAIM_RE`'s last-but-one branch,
`from\s+the\s+source[,:]?\s*$`, matches any line *ending* in "from the source" — including
`This requirement differs from the source` and `Nothing here is inherited from the source,`, which
assert the opposite of a verbatim claim. Today that is harmless: no such line exists, and one would
be swallowed by the very skip this item removes. The moment a claim with no block becomes a
finding, that looseness becomes a false-failure path, and an author writing an ordinary sentence
about the source would be told to produce a quotation. **False positives are the historically
shipped bug class in this repository**, so precision here is part of the work rather than a
follow-on to it.

## Completion condition

1. **The claim/block contract stated where standards authors will find it** — with the other
   document-shape rules, alongside §13, not only in `fidelity.mjs`'s header. It must say what
   phrasing constitutes a claim, that a fence, blockquote or list must follow it immediately, and
   that making the claim is what invites the check.
2. **A claim with no supported following block is a finding, never a silent skip.**
3. **The three valid forms remain accepted** — fence, blockquote and list — each held by a fixture,
   since the live corpus exercises only one of them.
4. **The measured plain-paragraph false pass reproduces red-first and is closed.** The shape above
   must fail before the change and be a finding after it.
5. **Mutation evidence that the new failure path bites**, per the discipline [[FE-09]] set and
   [[FE-33]] and [[FE-35]] followed: reintroduce the skip, watch the relevant tests go red, restore.
6. **All 25 existing claims remain verified, with byte-for-byte fidelity unweakened.** Normalization
   still collapses line wrapping only; backticks, punctuation and wording stay significant.
7. **A prose sentence ending in "from the source" does not become a false failure** — paired
   fixtures: a real claim that must be checked, and an ordinary sentence about the source that must
   not be. Whether that means tightening `CLAIM_RE`, requiring a trailing colon, or something else
   is the decision this item takes; it is not predetermined here.

## Notes

**One item, not two.** Splitting documentation from enforcement was considered and rejected for the
reason [[FE-35]] recorded: a written convention nobody enforces is still silently violable, and
enforcement without a written rule fails authors for a rule they cannot read. Here the two are
tied tighter still — *what to document* is exactly *what the checker must accept*, and item 7's
decision changes both at once.

**The pairing model is preserved.** `fidelity.mjs` takes the block immediately after the claim.
That is positional and deterministic: unlike the first-bold-span rule [[FE-35]] repaired, it has no
candidates to choose wrongly between, so nothing here reopens it. This item removes a silent skip
and states a contract; it is not a rewrite. If measurement during implementation shows the
positional model itself unsound, that is a stop-and-report, not licence to redesign the check.

**`diagrams.mjs` was measured and does not have this defect.** It binds to ordinary Markdown
` ```mermaid ` fences rather than a private convention, and compares each `.mmd` against *every*
embedded block rather than pairing one — having already been bitten by the pairing version and
fixed with a mutation test. No item is filed for it, and none is implied.

**No release consequence.** `fidelity` checks this repository's own documents against its own
specification, the way `inventory` and `levels` do. It adds no detector, extends no
`EVALUATED_RULES`, and says nothing about a target project, so no rule's level moves and nothing on
the frozen surface changes. No release is authorized by this item existing.

**`NOT_STARTED` means not scheduled.** Everything the work needs is recorded and nothing blocks
starting it.
