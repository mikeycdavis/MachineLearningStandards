## What

Three supported additions from the normative review, deliberately held back from 1.4.0.

## Why

They are requirements. Under the changelog policy at the top of `CHANGELOG.md`, adding a
requirement is MAJOR, and 1.4.0 was MINOR.

## Acceptance criteria

The item never carried explicit criteria, so they are stated here from its `## What` and `## Why`
rather than invented afterwards. Four states are distinguished, because collapsing them is how a
version bump gets mistaken for a release:

1. **Implemented** — the three additions exist as prose sections and catalog entries, with
   applicability declared. *Met.*
2. **Validated** — every gate this repository runs passes, with the guards observed failing first.
   *Met for eleven of twelve gates; `integrity` is outstanding by design, see below.*
3. **Locally versioned** — `VERSION`, `package.json` and `CHANGELOG.md` name the MAJOR that carries
   them, and no metadata claims a version the tree does not hold. *Met.*
4. **Published** — a tag and a push. *Not in this item's scope, not done, and separately
   authorised.*

Closure requires 1–3. FE-26 is untouched and remains open, so EP-12 and IN-04 stay `IN_PROGRESS`
regardless of what happens here.

## Notes

### The three additions, as drafted

| | Home | Catalog id | Shape |
|---|---|---|---|
| N3 | Standard 1 R6 | `framing.proxy-label-relationship-recorded` | Conditional: fires only where R1's predicted quantity and R3's decided quantity differ |
| N5 | Standard 5 R6 | `evaluation.external-validation-stated` | Universal wherever performance is reported |
| N8 | Standard 8 R5 | `leakage.pretraining-contamination-stated` | Conditional on a pretrained artifact or public benchmark taking part |

**N3's home was undetermined by the review and is settled here against examples**, which is what the
disposition asked for. Standard 1 holds both operands already — R1 states what is predicted, R3
names the decision — so the gap is answerable without a cross-standard lookup. Standard 3 was
compared and rejected: a proxy label is not a provenance defect, and Standard 3's scope would fire
the rule per dataset when the relation is a property of the problem.

**The churn case is a proxy case, not a control.** An earlier draft used it as an example of a
target and a decided quantity being the same; that is wrong. Predicting whether an account closes
does not measure whether an offer would change the outcome, and an account certain to close carries
the same label as one that would stay if asked. It is now the worked proxy example, and the control
is a grid-load forecast informing a decision that depends on grid load.

**N5 does not say internal evidence is worthless.** The obligation is to state validation provenance
and to withhold the transportability claim, not to disclaim relevance — a holdout estimate is a
sound estimate of the collection it was measured on, and that is what R1–R5 exist to protect.

**N8 distinguishes three exposure states, not two.** Established overlap, an undetermined corpus,
and exclusion supported by evidence. The claim is withheld in the first two, which closes the gap in
an earlier draft that forbade it only where exposure was unknown — known contamination would have
passed.

### Exemptibility: all three are `nonExemptible: false`

ADR 0003 refuses an exception only where granting it would amount to written permission to deceive,
and the criterion has only ever been applied to prohibitions. It does not reach these:

- What an exception here waives is **an incomplete record** — the sentence has not been written
  yet. That is a real, time-bounded, approvable state, and the honest neighbour already exists in
  the corpus: Standard 15 R4's "reproduction has not been attempted" is a respectable answer, not a
  waiver.
- What would be **permission to deceive** is the claim, not the silence — presenting a holdout
  figure as transportability, or a contaminated benchmark number as an unbiased estimate. Each of
  those is already forbidden by the second half of the rule's own normative sentence, and by
  `evaluation.no-training-metrics-as-production` and its neighbours, none of which an exception to
  these three would touch.

Nothing in ADR 0003 or in the exception machinery contradicts that, so the flag stays `false`.
Making these the first non-exemptible requirements would be a normative decision, and it is not
taken inside an implementation.

### Applicability for N8, declared rather than detected

`detect()` in `scripts/standards.mjs` builds a closed set of six trigger signals. A
`pretrained-artifact` string would sit outside it, never fire, and cause `explain` to tell a project
loading a released checkpoint that none of the rule's triggers had fired — a false reassurance,
which is worse than no signal. The trigger is therefore `training-code`, the narrowing lives in
Standard 8's scope prose, and the condition is carried in each project's `revisitWhen`. No detector
work was started.

### The baseline relock is outstanding, and deliberately so

`artifacts/catalog-baseline.json` is **unchanged in the working tree**. It is the artifact of a human
review, and standing permission to do the work is not that review. The proposed relock was prepared,
applied provisionally to measure, and reverted; with it applied the tree is 301/301 tests and 12/12
pipeline stages. Without it, exactly two assertions fail, both in `test/integrity.test.mjs`, both
saying the baseline should be brought up to date. That is the guard working, not a defect.

The proposed change adds the three entries and moves `reviewedOn` to 2026-09-06 and
`frameworkVersion` to `3.0.0` in one edit, so no state exists in which the baseline holds new rules
while naming the old carrying version. A mechanical comparison of the proposal against the current
file reports 53 existing entries compared, 0 changed, 0 removed, ordering preserved.
